# 運用の手順書（障害のとき、どうするか）

対象：公開後の「価格の取得」「サイト」「外部サービス（楽天・Yahoo!・Cloudflare・Supabase）」の障害。
最初に見るもの：GitHub Actions の「定期バッチ」と「価格の鮮度の見張り」、サイトの `/api/health`。

---

## 基本の守り（仕組み）

| 何が起きたか | 自動でどうなるか | あなたがすること |
|---|---|---|
| 1回だけ取得に失敗した | そのモールの価格は、前回のまま残る | 何もしない（次の回で直る） |
| 取得の失敗が 20% 以上 | バッチが「失敗」になり、Actions が知らせる | 下の「楽天・Yahoo! の障害」を見る |
| 1件の価格が 24時間を過ぎた | 画面に出さない・比べる対象から外す | 長く続くときだけ確かめる |
| 全体の価格が 12時間以上更新されていない | `/api/health` が 503 になり、見張りが Issue を作る | 下の「長く止まっているとき」を見る |
| 値が急に変わった（前回の50%以上） | その価格は保留（公開しない） | 本当に安くなったかを確かめる |

**送客リンク（ショップへのリンク）は、価格の取得とは別に動きます。** 価格が止まっていても、リンクは使えます。

---

## 1. 楽天・Yahoo! が一時的に使えない（503・タイムアウト）

1. GitHub の **Actions** → 「定期バッチ」の最新の実行を開き、エラーの行を読む。
2. 公式サイトのお知らせ（楽天：webservice.rakuten.co.jp／Yahoo!：developer.yahoo.co.jp）で、メンテナンスかを確かめる。
3. メンテナンスなら、終わるまで待つ。終わったら、Actions の画面から **Run workflow** で手動実行する。
4. 24時間以上続くときは「長く止まっているとき」へ。

## 2. APIのキーが無効になった（401・403）

1. Actions のログに「認証」「Forbidden」などが出ていたら、キーの問題。
2. 楽天：webservice.rakuten.co.jp でアプリの状態を確かめる。Yahoo!：developer.yahoo.co.jp で Client ID の状態を確かめる。
3. 新しいキーを、GitHub の **Secrets** に入れ直す（値はチャットに貼らない）。
4. Run workflow で手動実行して、取得が戻ったか確かめる。

## 3. APIの仕様が変わった（応答の形が変わった・件数が0になった）

1. ログに「件数 0」「採用 0」が続いていないかを見る。
2. 公式の仕様変更のお知らせを確かめる。
3. 直す必要があるときは、Claude に「このモールの応答が変わった」と伝えて、コードを直す。
4. 直るまでは、古い価格は24時間で自動的に消える。

## 4. 長く止まっているとき（12時間以上 / 24時間以上）

- 12時間を過ぎると、Issue が作られます（見張り）。
- 24時間を過ぎると、画面に出る価格は全部なくなります。商品ページは「いま比較できる価格がありません」と出ます。
- すぐに直せないときは、次の順で判断します。
  1. 原因を調べる（1〜3）。
  2. 直せない間は、そのまま待つ（価格が古いまま出すよりは安全です）。
  3. 「価格を一時的に止める」設定が必要になったら、Claude に頼んでください（まだ作っていません）。

## 5. サイトが表示されない（Cloudflare）

1. Cloudflare のダッシュボード → Workers & Pages → cospawan の **Deployments**（デプロイの履歴）を開く。
2. 直前の正常な版を選び、**Rollback**（戻す）を押す。
3. 戻したあと、トップと商品ページを開いて確かめる。

## 6. Supabase（データベース）が応答しない

1. Supabase のダッシュボードで、プロジェクトの状態（Status）を見る。
2. 障害のお知らせが出ていれば、終わるまで待つ。
3. 応答が戻ったら、Run workflow で手動実行する。

## 7. 商品の表示をやめたい（問題のある商品）

1. Supabase の **Table Editor** → **products** を開く。
2. その商品の `status` を **hidden** にする。
3. 戻すときは **active** にする。

## 8. 利用者から「価格がおかしい」と連絡が来た

1. 商品ページの「取得した日時」を見る。
2. 実際のショップの価格と照らし合わせる。
3. 違っていれば、その商品を hidden にして、原因を調べる。
4. 規約の「価格は変わることがある」を理由にせず、まず直すことを優先する。
